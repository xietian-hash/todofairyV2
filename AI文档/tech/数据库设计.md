# 数据库设计

## 1. 数据库

- 数据库类型：MySQL 8
- 默认数据库名：`tasksprite`
- ORM：Prisma
- Schema 文件：`apps/api/prisma/schema.prisma`

## 2. 核心表

### 2.1 `user`

- `id`
- `nickname`
- `avatar_url`
- `status`
- `last_login_at`
- `created_at`
- `updated_at`

### 2.2 `user_identity`

- `id`
- `user_id`
- `provider`
- `identity_key`
- `openid`
- `unionid`
- `created_at`
- `updated_at`

- 当前小程序登录使用 `provider=wechat_miniprogram`
- `(provider, identity_key)` 唯一

### 2.4 `user_tag`

### 2.5 `task`

- `user_id`

- `remark`

### 2.6 `todo`

- `id`
- `user_id`
- `task_id`
- `parent_task_id`
- `parent_todo_id`
- `is_sub_todo`
- `source_sub_task_id`
- `sub_task_index`
- `sub_task_title`
- `task_version`
- `todo_date`
- `trigger_type`
- `title`
- `remark`
- `tag_id`
- `tag_name`
- `status`
- `completed_at`
- `is_expired`
- `expired_at`
- `is_deleted`
- `deleted_at`
- `created_at`
- `updated_at`

说明：
- 父待办使用真实 `task_id`
- 子待办沿用业务语义，`task_id` 允许使用派生值，不对 `task.id` 建外键
- `(user_id, task_id, todo_date)` 唯一，保证同一待办生成幂等
- `source_sub_task_id` 保存子任务稳定标识；`sub_task_index` 仅表示当前展示顺序，因此拖动排序不会改变完成状态归属
- 一次性待办顺延不新增表字段，通过 `user_id + parent_task_id` 关联任务（包含已归档任务）的 `repeat_rule_json.weekdays=[]` 判断类型；接口返回的 `isOneTime` 为派生字段。凌晨1点在事务内移动未完成父项及全部有效子项的 `todo_date`，清除失效标记，保留原记录标识及完成进度；已完成父项不自动移动。

说明（2026-11-18）：服务酱渠道停用，`send_key` 仅为历史兼容保留，不再由业务读写，不影响飞书提醒判断；历史发送日志保留。不修改现有表结构或执行历史数据清理。

- 2026-11-18：测试发送使用正式通道名追加 `_test` 的独立通道，避免覆盖正式记录。正式去重排除历史测试来源 `manual_test_daily`、`manual_test_weekly`。索引和表结构不变。该判断用于成功后的顺序重跑保护，不提供并发请求的发送锁。

## 3. 关键索引

- `user_identity(provider, identity_key)` 唯一
- `user_tag(user_id, name)` 唯一
- `task(user_id, is_deleted, status)`
- `task(user_id, effective_start_date, effective_end_date)`
- `todo(user_id, task_id, todo_date)` 唯一
- `todo(user_id, todo_date, status)`
- `todo(user_id, parent_task_id)`
- `todo(user_id, parent_todo_id)`
- `todo_generation_log(user_id, todo_date)`
- `todo_generation_log(task_id, todo_date)`
- `todo_generation_log(user_id, trigger_type, created_at)`
- `notification_setting(user_id)` 唯一
- `notification_log(user_id, summary_date, channel)` 唯一
- `notification_log(user_id, created_at)`

## 4. 当前实现说明

- Prisma 已接入并用于正式读写
- 已建立基线 migration：`apps/api/prisma/migrations/20260501103500_init_mysql_schema`
- 本地查看迁移状态：
  - `pnpm run prisma:migrate:status`
- 开发新增字段推荐使用：
  - `pnpm run prisma:migrate:dev -- --name <migration_name>`
- 部署环境执行：
  - `pnpm run prisma:migrate:deploy`
- `prisma db push` 仅适合快速同步或原型阶段，不应替代正式 migration 流程
